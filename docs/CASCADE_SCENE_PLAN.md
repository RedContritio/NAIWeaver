# Cascade — Scene/Action tags + narration overlay (Plan B)

**Status:** proposal, awaiting approval
**Date:** 2026-06-05
**Origin:** user feature request — "should there be a Scene Description box describing what's going on in the scene?" plus "maybe add it as an overlay or caption."

---

## 0. The one thing to keep straight

This plan introduces **two separate inputs that look similar but do completely different jobs**. Do not merge them:

| | **Scene / Action field** | **Narration caption** |
|---|---|---|
| Input type | **booru tags** (`2girls, hugging, wide shot`) | **free natural-language text** ("They finally meet again.") |
| Job | feeds the NovelAI **base prompt** → drives generation | **burned onto the image** for storyboard narration |
| Touches generation? | **Yes** | **No** |
| Where it lives | per-beat (editor) + optional global (cast sheet) | per-beat, set at cast/playback time |

The user's correction was explicit: the generation-side input must be **tags, not a caption**; the caption is a *separate* narration layer the user types to "narrate your scenes." Conflating them is the one mistake this plan exists to avoid.

---

## 1. Why this is the architecturally correct change (research backing)

NovelAI V4/V4.5 splits every request into **one base prompt** + **N character prompts**. Per the official docs:

> "The base prompt determines the scene, style, and so on of the image. The character prompts allow you to describe each character in your scene."

> Subject-count tags (`2girls`) "should always go into the **base prompt**"; each character prompt uses `girl`/`boy` without a number.

> Interaction is expressed with `source#`/`target#`/`mutual#` action-tag prefixes on the character prompts.

So "what's happening in the scene" (subject count, the overall action, composition/camera, environment) is **exactly what the base prompt is for** — and a booru-tag Scene field maps 1:1 onto it. Today that base-prompt capability is underexposed: `environmentTags` is the only base-prompt input in the editor, and its label/hint ("ENVIRONMENT PROMPT / forest, night") quietly discourages putting scene-action tags there. Users have no obvious home for `2girls, wide shot, from above, hugging`.

Composition/camera vocabulary the Scene field should suggest/encourage (from Danbooru `tag_group:image_composition`):
- **Shot distance:** `portrait, upper body, cowboy shot, full body, wide shot, very wide shot, close-up`
- **Camera angle:** `from above, from below, from side, from behind, dutch angle, straight-on`
- **Scene-level:** `multiple views, pov, symmetry`

Tag suggestion already covers all of these — `TagService.getSuggestions` is backed by the full Danbooru tag list, so the Scene box gets autocomplete for free by reusing the existing `_handleTagInput` path in `director_view.dart`.

Sources:
- NovelAI multi-character docs: https://docs.novelai.net/en/image/multiplecharacters/
- Danbooru image-composition tag group: https://danbooru.donmai.us/wiki_pages/tag_group:image_composition
- Text-over-image legibility (scrim technique): https://www.smashingmagazine.com/2023/08/designing-accessible-text-over-images-part1/ , https://www.nngroup.com/articles/text-over-images/

## 2. Decisions locked in

- **Scene field shape:** *Split into two boxes.* Keep `ENVIRONMENT` (where), add a separate `SCENE / ACTION` (what's happening + composition). Both concatenate into the base prompt as tags.
- **Overlay:** a **typed narration caption**, not the scene tags. Display in-app; burn-in export is a fast-follow.
- **Delivery:** this doc first, review before code.

## 3. Current state (verified in code)

- `CascadeBeat` (`lib/features/tools/cascade/models/cascade_beat.dart`): has `environmentTags`, `characterSlots`, per-beat gen settings, `activeStyleNames`. JSON round-trips via `fromJson`/`toJson` with `??` fallbacks (good — backward-compatible additions are easy).
- `CascadeStitchingService.render` (`.../services/cascade_stitching_service.dart:51`): builds base caption as `[environmentTags] + [manualPrompt] + [globalStyle]`, then style prefix/suffix. Per-character prompts stitched separately into `NaiCharacter` objects.
- `DirectorView` (`.../widgets/director_view.dart`): the **editor**. Renders the `ENVIRONMENT PROMPT` field (with tag autocomplete via `_handleTagInput`), character slots, beat settings, styles.
- `CascadePlaybackView` (`.../widgets/cascade_playback_view.dart`): the **cast sheet**. `CHAR n TAGS` boxes (global appearances) + `GLOBAL STYLE / INJECTION` box. Generated bytes stored per beat in `CascadeState.beatPreviews`.
- `CascadeNotifier` (`.../providers/cascade_notifier.dart`): `updateActiveBeat`, `updateGlobalInjection`, `updateAppearance`, `setBeatPreview`. `CascadeState` holds `globalInjection`, `characterAppearances`, `beatPreviews`.
- Reusable infra: `CanvasFlattenService` (`lib/features/tools/canvas/services/canvas_flatten_service.dart`) already composites **pre-rendered text PNGs** onto images in an isolate via `compute()` + `package:image ^4.1.3` — the overlay burn-in path already exists.

## 4. Plan, phased

### Phase 1 — `SCENE / ACTION` tag field (per-beat) + stitcher wiring

**Goal:** give scene/action/composition tags their own home in the base prompt. Lowest risk, highest value. Fully backward-compatible.

**Model** (`cascade_beat.dart`)
- Add `final String sceneTags;` (default `""`).
- Constructor param `this.sceneTags = ""`.
- `fromJson`: `sceneTags: json['sceneTags'] ?? ""` (old cascades load fine).
- `toJson`: add `'sceneTags': sceneTags`.
- `copyWith`: add `String? sceneTags`.
- `addBeat`/`cloneBeat` in the notifier already copy `environmentTags`; mirror for `sceneTags` (clone carries it; `addBeat` may inherit last beat's like environment does — TBD, probably leave blank since action changes per beat).

**Stitcher** (`cascade_stitching_service.dart`)
- In `render`, prepend scene tags to `basePromptParts` **before** environment:
  ```
  if (beat.sceneTags.isNotEmpty)       basePromptParts.add(beat.sceneTags);
  if (beat.environmentTags.isNotEmpty) basePromptParts.add(beat.environmentTags);
  if (manualPrompt...)                 basePromptParts.add(manualPrompt);
  if (globalStyle...)                  basePromptParts.add(globalStyle);
  ```
  Order rationale: subject-count + action first (NAI reads base prompt left-to-right with front-loaded weight), environment next, user injection, style last.

**UI** (`director_view.dart`)
- Add a `_sceneController` + `_sceneFocusNode` (mirror the existing `_envController` exactly, incl. dispose + `_onFocusChanged` listener + `_syncControllers` text set).
- Render a new section **above** `ENVIRONMENT PROMPT`: header `SCENE / ACTION`, a `maxLines: 3` `TextField` wired through `_handleTagInput` (gets Danbooru autocomplete free) → `notifier.updateActiveBeat(beat.copyWith(sceneTags: v))`.
- Relabel the existing environment section hint to disambiguate ("where the scene takes place" vs new scene box "what's happening").

**l10n** (`app_en.arb` + `_ja`, `_zh`)
- `cascadeScenePrompt`: "SCENE / ACTION"
- `cascadeSceneHint`: "e.g. 2girls, hugging, wide shot, from above"
- Tweak `cascadeEnvHint` → "where: forest, night, indoors..."
- Regenerate `app_localizations*.dart` via `flutter gen-l10n`.

**Help dialog** (`cascade_help_dialog.dart`)
- Add a bullet under SETUP FLOW / a new line: "Scene / Action — base-prompt tags for what's happening (2girls, action, camera angle); Environment — where it happens."

**Test** (`test/cascade/`)
- Extend stitching coverage: a beat with `sceneTags` produces a base caption containing them, in the right order, ahead of environment. Round-trip `toJson`/`fromJson` preserves `sceneTags`, and a legacy JSON without the key loads with `""`.

**Risk:** minimal. Additive field, default-empty, old data loads. No migration script needed (the `??` fallback *is* the migration).

### Phase 2 — optional **Global Scene** tags (cast sheet)

**Goal:** the literal original request — a global scene box at Cast time for tags shared across every beat (e.g. `2girls, school uniform` that never changes). Stacks cleanly on Phase 1.

- `CascadeState`: add `globalSceneTags` (mirror `globalInjection` exactly).
- `CascadeNotifier`: add `updateGlobalSceneTags`.
- `setActiveCascade`/`exitCascadeMode`: reset it alongside `globalInjection`.
- `CascadePlaybackView._buildCastingSheet`: add a `RawAutocomplete` tag box above the global-style box (clone the existing global-injection autocomplete block).
- `CascadeStitchingService.render`: add a `globalSceneTags` param, inserted at the **front** of `basePromptParts` (global scene → per-beat scene → environment → injection → style).
- Pass it from the Generate button in `cascade_playback_view.dart`.

**Risk:** low. Same pattern as the existing global injection field.

---

### Phase 3 — Narration **caption overlay** (display-only)

**Goal:** per-beat typed narration, shown over the beat preview in-app. Non-destructive — never alters saved/exported files in this phase.

**Data:** caption text is **cast-time state**, not part of the saved cascade (it's narration for *this* run, like `characterAppearances`). Add `Map<int, String> beatCaptions` to `CascadeState` + `setBeatCaption(index, text)` on the notifier. (If users later want captions saved with the cascade, promote to the model — defer.)

**Input UI:** in `CascadePlaybackView`, near the beat thumbnail/generate controls, a small "caption" text field for the current beat (free text, **no** tag autocomplete — it's prose).

**Render (display):** overlay a caption band on the preview image wherever the beat preview is shown (the cast-sheet thumbnails and/or the main viewer when a preview is pushed). Use the **scrim** technique from the research:
- bottom-aligned gradient `Colors.transparent → black@~60%` (≈30% of height),
- caption text white, with a subtle shadow/outline for legibility on bright images,
- toggle to show/hide.
- Pure Flutter widget stack (`Stack` + `Positioned` + `Container(gradient)` + `Text`); no compositing needed for display.

**Risk:** low; it's a widget overlay. Main care: don't bake it into `beatPreviews` bytes (those get pushed to the main viewer / saved).

---

### Phase 4 (fast-follow) — caption **burn-in export** / storyboard strip

**Goal:** shareable frames with the narration baked in.

- Reuse `CanvasFlattenService`'s proven pattern: render the caption (scrim + text) to a transparent PNG at image resolution, then `img.compositeImage` it onto the beat bytes inside a `compute()` isolate. The service already accepts pre-rendered text PNGs (`textOverlays`) — generalize or add a small `CaptionBurnService` modeled on it.
- Two outputs worth offering: (a) single beat with caption burned in, (b) **vertical/horizontal storyboard strip** of all beats with captions — turns a cascade into a comic page.
- Gate behind an explicit export action so default saves stay clean.

**Risk:** medium (pixel work, but the hard parts already exist in the codebase). Keep separate from Phases 1–3.

## 5. Other improvements worth bundling (cheap, high-clarity)

1. **Relabel the cast sheet for clarity.** `cascadeGlobalStyle` is literally "GLOBAL STYLE / INJECTION" — two concepts, one box. With a Global Scene box arriving (Phase 2), split/relabel so each box has one obvious job: *Global Scene (tags)* / *Global Style* / *Char appearances*. Removes the "which box do I type in?" confusion the current UI invites.
2. **Section reorder in the editor** so the base-prompt fields read top-to-bottom in prompt order: `SCENE / ACTION` → `ENVIRONMENT` → `CHARACTER SLOTS`. Matches how the stitcher concatenates.
3. **Hint-driven guidance** in the Scene box: seed the hint with a composition example (`wide shot, from above`) so users discover camera/framing tags exist.
4. **"Apply scene to all beats" affordance** (small button) — common when the overall shot stays fixed and only character action changes. Cheap: map over beats with `copyWith(sceneTags:)`.
5. **Validation nudge (optional):** since Scene is tags, optionally flag obviously non-tag input (long sentences) with a soft hint "this looks like a caption — use the narration field for prose." Uses `TagService.hasTag` to sample tokens. Low priority; only if users misuse the box.

## 6. Suggested PR sequence

- **PR 1:** Phase 1 (Scene/Action field + stitcher + l10n + help + tests). Self-contained, shippable, no migration.
- **PR 2:** Phase 2 (Global Scene) + improvement #1 relabel + #2 reorder.
- **PR 3:** Phase 3 (display-only narration overlay).
- **PR 4:** Phase 4 (burn-in export / storyboard strip).

Each PR is independently valuable and independently revertable. Phases 1–2 are pure prompt plumbing (proven low-risk pattern); 3–4 are presentation and don't touch generation.

## 7. Open questions for review

- **Phase 1 `addBeat` inheritance:** should a new beat inherit the previous beat's `sceneTags` (like `environmentTags` does today), or start blank? Leaning blank — action typically changes per beat, environment often doesn't.
- **Caption persistence:** keep captions as ephemeral cast-time state (current plan) or save them in the cascade model so they travel with the sequence? Defer unless you want them saved.
- **Strip layout (Phase 4):** vertical (mobile-friendly) vs horizontal (filmstrip) vs both?
